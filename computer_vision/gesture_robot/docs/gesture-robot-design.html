Gesture-controlled robot: system design

A hand gesture seen by the XIAO Vision AI Camera drives a simulated robot in Gazebo. The ROS 2 link starts as a Python serial bridge and is later replaced by micro-ROS, without changing anything downstream. Development runs natively on an M4 Mac.

1Goals

  • Rock, paper, and scissors each trigger a distinct, repeatable robot action in Gazebo.
  • A dropped gesture, unplugged camera, or lost Wi-Fi link always stops the robot within about 2 seconds.
  • The camera-to-ROS link can be swapped from a Python bridge (v1) to micro-ROS (v2) with no change to the behavior node, the simulation, or the topic.
  • The project produces measurable v1 vs v2 results for a portfolio write-up.

Out of scope: training a custom model, running on real robot hardware, and continuous hand tracking. The bounding-box center is carried in the message so continuous control can be added later.

The heartbeat makes ros2 topic hz meaningful, lets late subscribers learn the current state, and gives the behavior node something to time out on. An integer gesture ID avoids string buffers on the microcontroller. The header still has a frame_id string, so v2 assigns it once at startup (see 6.6).

5Links and wire formats

Camera link (both versions)

The Vision AI V2 talks to the ESP32-C3 over a hardware UART through the XIAO header at 921600 baud, which is the SSCMA default and too fast for software serial. v1 uses this UART too, instead of the library's I2C default, so the physical link is identical when you move to v2.

Inference runs continuously after one command:

AT+INVOKE=-1,0,1\r
ArgumentValueWhy
N_TIMES-1Run until told to stop
DIFFERED0Send every frame, because the debouncer counts consecutive frames
RESULT_ONLY1Leave out the base64 image to keep the link light

Each reply is framed as \r, a JSON body, then \n. Inference results arrive as event replies ("type": 1, "name": "INVOKE"). Each box is an array of [x, y, w, h, score, target], with score from 0 to 100 and target as the model's class index. Confirmed on hardware: x and y are the box center, reported in the 240×240 preview frame rather than the model's 192×192 input, because the device rescales boxes before sending them. Neither the AT spec nor the Seeed wiki states this, and Seeed's own camera_web_server example is self-contradictory about it, so it was measured from a known preview frame.

{"type":1,"name":"INVOKE","code":0,
 "data":{"count":8,"perf":[8,365,0],"boxes":[[87,83,77,65,70,1]]}}

v1 gets these fields through the SSCMA library. v2 parses them itself.

Host link, v1

USB serial (CDC) to /dev/cu.usbmodem… on the Mac, one JSON object per line. Field names are short to keep lines small.

{"g":1,"c":0.87,"x":0.512,"y":0.430,"t":48213}
FieldMeaning
gGesture constant from the message definition (0, 1, 2, or 255)
cConfidence, 0 to 1
x, yNormalized box center
tDevice millis(), for debugging only

Host link, v2

Wi-Fi to the Mac, UDP port 8888, XRCE-DDS between the device and the micro-ROS agent running natively on the Mac. The agent then presents the device as a normal ROS 2 node. The firmware needs the Mac's IP address, so reserve it in your router.

6Components

6.1 Shared debouncer (C++)

Detection models flicker between classes on transitional frames, so the device only reports a gesture after it has been seen for several frames in a row. This code uses no Arduino or ESP-IDF calls, so both firmware versions compile the same files and you can unit-test it on your PC.

firmware/common/gesture_debouncer.h

#pragma once
#include <cstdint>

namespace gesture {

enum class Id : uint8_t { Paper = 0, Rock = 1, Scissors = 2, None = 255 };

struct Detection {
  bool valid;           // false when the frame had no box
  uint8_t model_class;  // raw class index from the model
  float score;          // 0 to 1
  float cx, cy;         // normalized box center
};

struct Event {
  Id gesture;
  float confidence;
  float cx, cy;
};

struct Config {
  uint8_t frames_to_confirm = 5;
  float min_score = 0.60f;
  uint32_t none_timeout_ms = 500;
};

class Debouncer {
 public:
  explicit Debouncer(const Config& cfg) : cfg_(cfg) {}
  // Call once per inference frame. Returns true and fills `out`
  // only when the confirmed gesture changes.
  bool update(const Detection& det, uint32_t now_ms, Event& out);
  Id current() const { return state_; }

 private:
  static Id map_class(uint8_t model_class);
  Config cfg_;
  Id state_ = Id::None;
  Id candidate_ = Id::None;
  uint8_t streak_ = 0;
  uint32_t last_seen_ms_ = 0;
};

}  // namespace gesture

firmware/common/gesture_debouncer.cpp

#include "gesture_debouncer.h"

namespace gesture {

// The only place that knows the model's class order.
Id Debouncer::map_class(uint8_t model_class) {
  static const Id kMap[] = {Id::Paper, Id::Rock, Id::Scissors};
  return model_class < 3 ? kMap[model_class] : Id::None;
}

bool Debouncer::update(const Detection& det, uint32_t now_ms, Event& out) {
  // Unsigned subtraction stays correct across millis() wraparound.
  const bool gap = now_ms - last_seen_ms_ > cfg_.none_timeout_ms;
  if (gap) {
    // Frames on either side of a long gap are never consecutive.
    candidate_ = Id::None;
    streak_ = 0;
  }

  if (det.valid && det.score >= cfg_.min_score) {
    Id id = map_class(det.model_class);
    last_seen_ms_ = now_ms;
    if (id == candidate_) {
      if (streak_ < 255) ++streak_;
    } else {
      candidate_ = id;
      streak_ = 1;
    }
    if (streak_ >= cfg_.frames_to_confirm && id != state_) {
      state_ = id;
      out = {id, det.score, det.cx, det.cy};
      return true;
    }
    return false;
  }

  // Frames without a usable box don't break the streak on their own.
  if (gap && state_ != Id::None) {
    state_ = Id::None;
    out = {Id::None, 0.0f, 0.0f, 0.0f};
    return true;
  }
  return false;
}

}  // namespace gesture

A gap longer than none_timeout_ms clears any partial streak, not only a confirmed gesture, so frames on either side of a dropout never count as consecutive. A single missed frame still keeps the streak, which is what lets the count survive normal detector flicker.

6.2 Firmware v1 (Arduino)

Two installs cover this sketch: the esp32 board package by Espressif Systems, which is in the default Boards Manager list so no extra URL is needed, and the Seeed Arduino SSCMA library, accepting its ArduinoJson dependency. Select board XIAO_ESP32C3 and leave USB CDC On Boot enabled, which is this board's default, so Serial goes over USB and UART0 stays free for the Vision AI V2. Symlink the two common/ files into the sketch folder instead of copying them, so v1 and v2 keep one source of truth: the IDE's builder follows symlinks and lists them as tabs. Flash over USB on the /dev/cu.usbmodem… port; the IDE calls the board "Unconfirmed", which is normal for the C3's native USB, so pick it by hand.

firmware/v1_arduino/gesture_camera_v1/gesture_camera_v1.ino

#include <HardwareSerial.h>
#include <Seeed_Arduino_SSCMA.h>
#include "gesture_debouncer.h"

// Boxes come back in the 240x240 preview frame, not the model's 192x192 input.
constexpr float kImgW = 240.0f;
constexpr float kImgH = 240.0f;
constexpr uint32_t kHeartbeatMs = 1000;

// 1 also prints every raw box, to confirm the score scale and the class order.
#define LOG_RAW_BOXES 0

HardwareSerial atSerial(0);  // UART to the Vision AI V2 through the XIAO header
SSCMA AI;
gesture::Debouncer deb(gesture::Config{});
gesture::Event last{gesture::Id::None, 0.0f, 0.0f, 0.0f};
uint32_t lastSentMs = 0;

void emit(const gesture::Event& e) {
  Serial.printf("{\"g\":%u,\"c\":%.2f,\"x\":%.3f,\"y\":%.3f,\"t\":%lu}\n",
                static_cast<unsigned>(e.gesture), e.confidence,
                e.cx, e.cy, static_cast<unsigned long>(millis()));
  lastSentMs = millis();
}

void setup() {
  Serial.begin(115200);
  if (!AI.begin(&atSerial)) Serial.println("SSCMA begin failed");
}

void loop() {
  // The library builds AT+INVOKE=<times>,<!filter>,<filter>, so filter=true
  // sends AT+INVOKE=1,0,1: every frame, no image.
  if (AI.invoke(1, true, false) != 0) return;  // 0 means success

  gesture::Detection det{false, 0, 0.0f, 0.0f, 0.0f};
  for (auto& b : AI.boxes()) {                    // keep the highest-scoring box
#if LOG_RAW_BOXES
    Serial.printf("raw x=%u y=%u w=%u h=%u score=%u target=%u\n", b.x, b.y, b.w,
                  b.h, b.score, b.target);
#endif
    float s = b.score / 100.0f;
    if (!det.valid || s > det.score) {
      // x, y are already the box center.
      det = {true, static_cast<uint8_t>(b.target), s, b.x / kImgW, b.y / kImgH};
    }
  }

  gesture::Event ev;
  if (deb.update(det, millis(), ev)) {
    last = ev;
    emit(last);
  } else if (millis() - lastSentMs >= kHeartbeatMs) {
    emit(last);                                   // heartbeat with current state
  }
}

The invoke() arguments are a trap. The library builds the command as AT+INVOKE=<times>,<!filter>,<filter>, so its second argument sets DIFFERED inverted and RESULT_ONLY directly. Passing false sends AT+INVOKE=1,1,0, which tells the camera to reply only when the result changes and to include the base64 image: that starves the debouncer of the consecutive frames it counts, and floods the UART. AI.invoke(1, true, false) sends AT+INVOKE=1,0,1, which is the row in section 5. Seeed's own inference_uart example passes this argument as IMAGE_SHOW, which reads backwards from what it does.

Confirmed on hardware, 2026-09-19: boxes report the center in a 240×240 frame, scores arrive as 0 to 100 (53 to 88 observed), and the class order matches map_class() as written, paper 0, rock 1, scissors 2. The camera also applies its own confidence threshold, set from SenseCraft with AT+TSCORE and kept in flash across power cycles. With that at 50, the debouncer's min_score of 0.60 is the gate that actually decides.

6.3 Python bridge (v1 only)

Reads JSON lines, validates them, and publishes Gesture messages. It runs inside pixi shell on the Mac. It reconnects if the camera is unplugged and counts bad lines rather than crashing.

ros2_ws/src/gesture_bridge/gesture_bridge/serial_bridge.py

import json
import threading
import time

import rclpy
import serial
from rclpy.node import Node
from rclpy.qos import HistoryPolicy, QoSProfile, ReliabilityPolicy

from gesture_msgs.msg import Gesture

GESTURE_QOS = QoSProfile(
    history=HistoryPolicy.KEEP_LAST,
    depth=10,
    reliability=ReliabilityPolicy.RELIABLE,
)


class SerialBridge(Node):
    def __init__(self):
        super().__init__('gesture_bridge')
        # Find yours with: ls /dev/cu.usbmodem*
        self.port = self.declare_parameter('port', '/dev/cu.usbmodem101').value
        self.baud = self.declare_parameter('baud', 115200).value
        self.frame_id = self.declare_parameter('frame_id', 'gesture_camera').value
        self.pub = self.create_publisher(Gesture, '/gesture/event', GESTURE_QOS)
        self.bad_lines = 0
        threading.Thread(target=self._read_loop, daemon=True).start()

    def _read_loop(self):
        while rclpy.ok():
            try:
                with serial.Serial(self.port, self.baud, timeout=1.0) as ser:
                    self.get_logger().info(f'Connected to {self.port}')
                    while rclpy.ok():
                        raw = ser.readline()
                        if raw.endswith(b'\n'):
                            self._handle(raw)
            except serial.SerialException as exc:
                self.get_logger().warn(f'Serial error: {exc}. Retrying in 2 s.')
                time.sleep(2.0)

    def _handle(self, raw):
        try:
            data = json.loads(raw)
            gesture = int(data['g'])
            if gesture not in (0, 1, 2, 255):   # PAPER, ROCK, SCISSORS, NONE
                return self._drop(raw)
            msg = Gesture()
            msg.header.stamp = self.get_clock().now().to_msg()
            msg.header.frame_id = self.frame_id
            msg.gesture = gesture
            msg.confidence = float(data['c'])
            msg.bbox_cx = float(data['x'])
            msg.bbox_cy = float(data['y'])
        except (ValueError, KeyError, TypeError):
            return self._drop(raw)
        self.pub.publish(msg)

    def _drop(self, raw):
        self.bad_lines += 1
        self.get_logger().debug(f'Dropped line {raw!r} ({self.bad_lines} total)')


def main():
    rclpy.init()
    node = SerialBridge()
    try:
        rclpy.spin(node)
    except KeyboardInterrupt:
        pass
    finally:
        node.destroy_node()
        rclpy.try_shutdown()

Corrected on this build, 2026-09-23: the plan assumed the generated message class rejects out-of-range values, such as a gesture of 300, with an AssertionError. On RoboStack Jazzy it does not: msg.gesture = 300 stores 300 with no check, and the value silently wraps at serialization (300 becomes 44), which would reach the behavior node as a bogus gesture. So the bridge validates the range itself, as above, and AssertionError is dropped from the except. In the shipped code this parsing lives in a small gesture_bridge/parser.py with no ROS imports, so it can be unit-tested with plain Python; the node just turns a parsed line into a message and publishes it.

6.4 Behavior node (C++)

Written with rclcpp in an ament_cmake package. It subscribes to /gesture/event, acts only when the gesture changes, and stops the robot if messages stop arriving.

ResponsibilityDesign
Change detectionKeep active_gesture_. Heartbeats with the same value do nothing except refresh the watchdog.
WatchdogA 5 Hz wall timer sets the active gesture to NONE if nothing has arrived for watchdog_timeout_s (2 s, or two missed heartbeats).
Velocity outputA 10 Hz timer publishes the velocity for the active gesture on cmd_vel_topic. NONE publishes zero. The topic is a parameter so turtlesim and TurtleBot3 use the same code.
Hand outputOn change, publish one JointTrajectory point to /hand_controller/joint_trajectory. NONE holds the last pose.
MappingLoaded from a YAML file per robot, so remapping gestures needs no rebuild.

ros2_ws/src/gesture_behavior/config/turtlesim.yaml

gesture_behavior:
  ros__parameters:
    robot: turtlesim                  # turtlesim, turtlebot3, or hand
    cmd_vel_topic: /turtle1/cmd_vel
    watchdog_timeout_s: 2.0
    velocities:
      rock:     {linear: 0.0, angular: 0.0}
      paper:    {linear: 1.0, angular: 0.0}
      scissors: {linear: 0.0, angular: 1.5}

turtlebot3.yaml is the same shape with cmd_vel_topic: /cmd_vel and gentler speeds (about 0.15 linear, 0.6 angular). hand.yaml sets robot: hand and move_time_s: 0.8.

Check: turtlesim takes geometry_msgs/Twist. Once the TurtleBot3 simulation is running, check ros2 topic info /cmd_vel, because Jazzy setups may expect geometry_msgs/TwistStamped. Support both types behind a parameter.

Done 2026-09-23 (phase 3, turtlesim). The node ships with the change detection, 10 Hz velocity timer, and 5 Hz watchdog above, publishing Twist from turtlesim.yaml. Hand JointTrajectory output and the TwistStamped option are deferred to phase 4, where a sim that needs them exists to test against.

macOS build trap. On RoboStack (conda), a C++ node that uses a message package aborts at startup with symbol not found in flat namespace '_PyExc_RuntimeError'. The message package's CMake targets (both ament_target_dependencies and ${<pkg>_TARGETS}) transitively pull in its rosidl_generator_py library, which loads eagerly but needs libpython, which a standalone C++ binary does not link. Fix in CMakeLists.txt: link only the <pkg>::<pkg>__rosidl_typesupport_cpp targets and add target_link_options(<node> PRIVATE -Wl,-dead_strip_dylibs), which drops the unused Python libraries from the load commands. The middleware still dlopens the real typesupport at runtime, so it is safe, and it matches how the prebuilt RoboStack binaries are linked. This applies to every C++ node, so phase 4's additions need the same two lines.

6.6 Firmware v2 (ESP-IDF + micro-ROS)

Two FreeRTOS tasks keep camera parsing and networking apart, so a slow Wi-Fi moment never makes the device miss frames.

Agent connection. Follow the standard micro-ROS reconnection pattern, so the device survives the agent restarting or Wi-Fi dropping:

Use rmw_uros_ping_agent() to test the link in each state.

firmware/v2_espidf/main/at_client.cpp (excerpt)

static const char kInvoke[] = "AT+INVOKE=-1,0,1\r";
static constexpr size_t kMaxReply = 4096;

void vision_task(void*) {
  uart_write_bytes(UART_NUM_1, kInvoke, sizeof(kInvoke) - 1);
  std::string line;
  uint8_t byte;
  for (;;) {
    if (uart_read_bytes(UART_NUM_1, &byte, 1, pdMS_TO_TICKS(50)) != 1) {
      rearm_if_stalled();                 // AT+BREAK, then kInvoke again
      continue;
    }
    if (byte == '\r') { line.clear(); continue; }   // start of a reply
    if (byte != '\n') {
      if (line.size() < kMaxReply) line.push_back(static_cast<char>(byte));
      continue;
    }
    handle_reply(line);  // parse JSON, keep INVOKE events, best box, debounce, queue
  }
}

firmware/v2_espidf/main/ros_link.cpp (excerpt)

static gesture_msgs__msg__Gesture g_msg;

void init_message() {
  gesture_msgs__msg__Gesture__init(&g_msg);
  // The header's frame_id is a string, so allocate it once here.
  rosidl_runtime_c__String__assign(&g_msg.header.frame_id, "gesture_camera");
}

void publish_event(const gesture::Event& ev) {
  int64_t ns = rmw_uros_epoch_nanos();   // valid after rmw_uros_sync_session()
  g_msg.header.stamp.sec = static_cast<int32_t>(ns / 1000000000LL);
  g_msg.header.stamp.nanosec = static_cast<uint32_t>(ns % 1000000000LL);
  g_msg.gesture = static_cast<uint8_t>(ev.gesture);
  g_msg.confidence = ev.confidence;
  g_msg.bbox_cx = ev.cx;
  g_msg.bbox_cy = ev.cy;
  if (rcl_publish(&g_pub, &g_msg, nullptr) != RCL_RET_OK) {
    ++g_publish_failures;
  }
}

from launch.actions import DeclareLaunchArgument

transport = LaunchConfiguration('transport')

    DeclareLaunchArgument('transport', default_value='serial'),
    DeclareLaunchArgument('port', default_value='/dev/cu.usbmodem101'),
    DeclareLaunchArgument('robot', default_value='turtlesim'),

]

bridge = Node(
    package='gesture_bridge', executable='serial_bridge',
    parameters=[{'port': LaunchConfiguration('port')}],
    condition=IfCondition(EqualsSubstitution(transport, 'serial')),
)

agent = Node(
    package='micro_ros_agent', executable='micro_ros_agent',
    arguments=['udp4', '--port', '8888'],
    condition=IfCondition(EqualsSubstitution(transport, 'microros')),
)

10Testing and benchmarks

Without hardware

  • Debouncer unit test. tests/debouncer_test.cpp is a self-contained runner, with no test framework to install. From the repo root: mkdir -p build && g++ -std=c++17 -Wall -Wextra -Werror -Ifirmware/common tests/debouncer_test.cpp firmware/common/gesture_debouncer.cpp -o build/debouncer_test && build/debouncer_test. Its 24 cases cover flicker, low scores, the score threshold, a single missed frame, gaps that break a streak, the 500 ms timeout, switching gestures, unknown classes, and millis() wraparound.
  • Bridge parser test. tests/bridge_parser_test.py runs with plain Python and no ROS environment, because the parsing lives in the ROS-free gesture_bridge/parser.py: python3 tests/bridge_parser_test.py. It covers each gesture parsing, extra fields ignored, and dropping garbage, missing fields, bad types, and out-of-range gestures. For the full serial-read and publish path, a pseudo-terminal harness (Python's pty, no socat needed) points the running node at a virtual serial pair and counts what publishes on /gesture/event; that one needs the ROS environment. The older socat route still works too: socat -d -d pty,raw,echo=0 pty,raw,echo=0, point the bridge at one end, write JSON lines into the other.

Acceptance test (run for v1 and again for v2)

Ten trials per gesture, plus two recovery checks: unplug the camera (v1) or stop the agent (v2), and confirm the robot stops within 2 s. Pass means at least 9 of 10 correct responses per gesture and both recovery checks.

11Verify on your hardware

These points came from documentation and examples rather than the device. The first group is settled by phase 1; the rest still need checking when you reach them.

Answered by the hardware

  • Class order is paper 0, rock 1, scissors 2, which matches map_class() as written, so no edit was needed.
  • Box x, y are the center, in a 240×240 frame. The model's input is 192×192, but the device rescales boxes to the preview frame before reporting them, so kImgW and kImgH are 240. No source states this, so it was measured by comparing a logged box against the preview frame it was drawn on.
  • Scores arrive as 0 to 100, 53 to 88 observed in practice, so b.score / 100.0f is right.
  • UART0 through the XIAO header reaches the Vision AI V2 at 921600 baud with USB CDC On Boot enabled, which is the same physical link v2 will use.
  • The camera applies its own confidence threshold before the firmware sees anything. It is device state (AT+TSCORE), set from SenseCraft and kept in flash across power cycles. Keep it below the debouncer's min_score, or the debouncer's threshold never decides anything.
  • The camera firmware accepts the three-argument AT+INVOKE that the SSCMA library sends.

Still open

  • Each AT reply arrives on a single line. The library handles framing for v1, so this only matters when you write your own parser in step M4.
  • The message type the TurtleBot3 simulation expects on /cmd_vel.
  • Every package in the setup command resolves in RoboStack for macOS Apple Silicon.
  • The micro-ROS agent is available prebuilt, or builds from source on macOS.
  • Gazebo Harmonic runs your hand and TurtleBot3 models on the Mac with the server and GUI in separate terminals.

12Build plan by phase

What to build, in what order, and how to know a phase is finished. Sections 4 to 10 hold the details for each piece.

Phase 1: camera and firmware v1

Goal: the camera prints clean gesture events over USB.

  1. Deploy the Gesture Detection model from SenseCraft AI to the Vision AI V2. In the live preview, hold up each gesture and write down the class index it reports.
  2. Set up the Arduino IDE: ESP32 board package, board XIAO_ESP32C3, USB CDC On Boot enabled, and the Seeed_Arduino_SSCMA library.
  3. Add firmware/common/gesture_debouncer.h and .cpp (section 6.1) and run the host unit test before touching hardware.
  4. Write the sketch (section 6.2). First log raw boxes to confirm the score scale, the coordinate resolution, and whether x, y are the center or the corner, then fill in kImgW and kImgH.
  5. Update map_class() if your class order differs from the preview.

Done when: the Serial Monitor at 115200 baud shows one JSON line per gesture change, a heartbeat line each second, and a 255 line about half a second after your hand leaves the frame.

Done 2026-09-19. All three behaviors confirmed on the device, with the findings in section 11. Two fixes came out of it: the invoke() arguments in 6.2, and clearing a partial streak across a long gap in 6.1.

Phase 2: contract and bridge

Goal: those events arrive on /gesture/event.

  1. Create gesture_msgs (ament_cmake) with Gesture.msg from section 4, then colcon build and check ros2 interface show gesture_msgs/msg/Gesture.
  2. Create gesture_bridge (ament_python) with serial_bridge.py from section 6.3, and register the entry point serial_bridge = gesture_bridge.serial_bridge:main in setup.py.
  3. Close the Arduino Serial Monitor, then run the bridge with your port parameter.
  4. Test the failure paths with the virtual serial pair from section 10: malformed lines, out-of-range values, and unplugging the camera.

Done when: ros2 topic echo /gesture/event shows a message on each gesture change, ros2 topic hz /gesture/event reads about 1 Hz at rest, and bad input never kills the node.

Done 2026-09-23. All three gestures and NONE confirmed on /gesture/event with correct values and frame_id gesture_camera, and the 1 s heartbeat visible in the message stamps. The out-of-range finding above came out of the failure-path testing.

Phase 3: behavior node and turtlesim

Goal: gestures drive a robot, and losing the camera stops it.

  1. Create gesture_behavior (ament_cmake, C++) with the responsibilities in section 6.4: change detection, a 10 Hz velocity timer, and a 5 Hz watchdog.
  2. Add config/turtlesim.yaml, and turtlebot3.yaml later with gentler speeds.
  3. Create gesture_bringup with bringup.launch.py and its four arguments (section 8), starting with transport, port, and robot.
  4. Check the message type with ros2 topic info before assuming Twist.

Done when: rock stops the turtle, paper drives it, scissors rotates it, unplugging the camera stops it within 2 s, and one launch command starts the whole stack.

Done 2026-09-23. All five confirmed on hardware from a single ros2 launch gesture_bringup bringup.launch.py, plus the recovery path: after an unplug the bridge reconnects on its own (retries every 2 s, forever, by design) and gestures resume with no restart. The behavior-node logic was also checked headlessly before the hardware run. The one build issue was the macOS linker trap noted in 6.4.

Phase 4: hand mimic, then Gazebo

Goal: a five-finger hand mirrors your gesture.

Split into two PRs once work started, mirroring how phases 1-3 each shipped as their own PR: 4a is the hand in RViz2 with ros2_control mock hardware; 4b, a follow-up, adds TurtleBot3 and moves the same hand to Gazebo Harmonic. The split kept 4a's diff small enough that real-hardware testing could catch a geometry bug before 4b builds anything on top of it.

4a steps:

  1. Create gesture_sim with simple_hand.urdf.xacro and hand_controllers.yaml (section 6.5). Poses ended up living in gesture_behavior/config/hand.yaml alongside turtlesim.yaml and turtlebot3.yaml, not a separate hand_poses.yaml — matching that existing per-robot pattern instead of adding a second one. Check the model with xacro and check_urdf before launching anything.
  2. Add the stage A launch: robot_state_publisher, ros2_control_node, the controller spawners, and RViz2. Test the poses by hand with ros2 topic pub before wiring the gestures in.
  3. Extend the behavior node to publish JointTrajectory when robot is hand.

4a done when: all three poses appear in RViz2 within about a second of the gesture, and unplugging the camera holds the hand's last pose instead of resetting it.

Done 2026-09-24. All three poses confirmed on hardware, plus the hold-last-pose behavior across both a hand leaving the frame and a camera unplug/replug. One real bug came out of it: each finger's joint mounted with no pitch, so 0 rad pointed straight up out of the palm's face instead of forward, so "curled" looked flat and spread instead of a closing fist. Fixed by pitching the mount 90 degrees so 0 rad extends forward and larger values curl down into the palm, verified against the actual palm-to-fingertip transform for all three poses rather than by eye alone. A second pass turned off the saved RViz view's TF display, since the axis markers and overlapping frame-name labels were hiding the actual hand shape, especially in the rock pose where curled fingers correctly tuck under the palm and out of view from above.

4b steps (not started):

  1. Install the Gazebo packages (ros-jazzy-ros-gz, ros-jazzy-gz-ros2-control, ros-jazzy-turtlebot3-gazebo) — not needed for 4a.
  2. Spawn TurtleBot3 Burger with its lidar removed (section 2's Gazebo sensors note), since nothing here reads TurtleBot3's own sensors.
  3. Launch with use_gazebo:=true and open the GUI in a second terminal.

4b done when: the same three poses appear in Gazebo with no change to the behavior node, TurtleBot3 drives alongside the hand, and you have a short screen recording for the write-up.
